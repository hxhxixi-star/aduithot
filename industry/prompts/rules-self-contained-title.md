
【标题自洽规则 — 让读者不点开就知道"这是关于谁的什么事"】

1. 标题必须点出核心主体：标准名 / 体系名 / 机构名 / 项目名。
2. 原标题已经清楚点出主体的：英文标题翻译成中文、中文标题保持原意，不要为改写而改写。
3. 原标题只是版本号 / 代号 / 没信息量的 teaser（如 "v2.1.159"、"Small is a feature"、"Day 1"、"重磅发布"）时，结合【来源】和正文把主体补进标题。例：原标题 "v2.1.159" + 来源 "SLCP 工具包：GitHub Releases" → "SLCP 工具包 v2.1.159 发布"。
4. 补主体只能用【来源】或正文里真实出现的名字。正文和来源都没点出具体版本时，用上位词（如"社会责任审核体系"）兜底，绝不凭"行业常识"编一个具体版本 / 条款 / 数字。
5. 原标题表达的【文章类型和核心动作】是硬边界：How / Why / Guide / Analysis / Review / Checklist 这类解释、分析、教程或解读标题，中文标题必须保留这个类型；不能因为正文谈到一个已经存在的标准、体系或新清单，就改写成“发布 / 推出 / 生效 / 修订”。只有原标题明确宣布了发布、推出、生效或修订，中文标题才能使用对应动作。保留文章类型不等于删主体：仍须按第 1-4 条补全正文或来源明确给出的机构、标准、项目名。
   例：原标题 "How the updated MRSL simplifies chemical management" → "新版 MRSL 如何简化化学品管理"，不能写成 "ZDHC 发布新版 MRSL"。
   例：原标题 "How to prepare wage and hour records for a social audit" + 来源和正文明确是 amfori → "amfori 提示如何准备社会责任审核的工资工时记录"，不能只写成缺主体的 "如何准备工资工时记录"。
